### Part C - control design choices

Now to actually code the controller. A PID controller helps regulate the controller outputs and inputs which helps prevent 
overshooting or undershooting the target by regulating the speed of the mechanism turnign the wheel from its intial to its target
position. They do this by implementing three variables, proportional, which scales the speed of the mechanism at
the current error so the wheel so it can hit its target approriately without over or undershooting.
The integral, which builds error overtime and assits the wheel to turn to its target effeciently
if stuck short of the target. Finally, deritative which predicts future error as it calcualtes how fast you are approaching the target.
With this synchorinization of the three variables, a steady autonomous controller can be achieved. 

(The full process of the code can be viewed in the doc 29-32)

Note: An integral limit was also implemented because integral is infamous for building error overtime, and without a limit,
it would continously build up error overtime and cause integral windup, which is when a motors hits it maximum limit but the integral
keeps on pushing which would cause severe overshoots.

An error which prevented me from even starting this was accurately valueing the PID terms and integral limit. First I wrote all the code
out with random values in the 4 variables and decided to just do trial and error. But this worked to no avail. So I tried to search
up alternative solution until I came across the strategy called heuristic tuning. This is a very useful method that is used to 
adjust the parametres of a system to reach its ideal values. 

Briefly:
1. I set all the 3 other variables to zero whilst keeping K at a low starting point (1.0).
2. Then I go up in increments of doubling until it gave me a proper value where the the graph reaches steady oscillation
3. Now then, I add integral as a non zero starting value and repeat the same, Looking for visual cues that flatten the once oscillating
line to its target.
4. Then I add the deritative and executed the same, looking for a clean flat line.
5. For the Integral limit, I simply brute-force trial and errored it but went up by integrals (1,2,4,8,16,32) until my overshooting
data was stable enough.

An error encountered during the program was not realising we even needed a limit. Thus, as said, would cause integral windup
